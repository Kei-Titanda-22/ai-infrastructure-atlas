# Architecture

## Constitutional boundary

`docs/constitution.md` is an architectural constraint, not a documentation appendix. In particular: primary-source preference, numeric provenance, source-term review, fact/analysis separation, secret handling, and legal review gates constrain future ingestion and deployment choices.

## Static-first

```text
source registry + source policy registry
        ↓
human-reviewed profile/analysis + verified objective data
        ↓
constitution/data validation
        ↓
Astro content schema validation
        ↓
Astro static build
        ↓
Pagefind post-build indexing
        ↓
dist/
        ↓
GitHub Pages
```

No runtime backend is required for v0.1.

## Future automated update boundary

Automation is allowed to update only data for which the relevant Source Policy permits the intended access/use:

- raw market snapshots (not real-time distribution)
- raw financial statements
- normalized financial metrics
- earnings metadata
- selected sector KPIs

Automation is **not** allowed to overwrite:

- strengths
- risk interpretation
- moat judgment
- final AI sensitivity score
- final investment conclusion

Those remain human-reviewed fields.

## Planned ingestion pipeline

```text
Approved primary source / licensed provider
        ↓
Source Policy pre-check
        ↓
Scheduled GitHub Action
        ↓
raw/ immutable snapshot
        ↓
normalizer + provenance validation
        ↓
derived JSON
        ↓
site build
        ↓
Pages deploy
```

A Source with `reviewStatus != reviewed` or with unknown/restricted automated-retrieval terms does not enter the automated pipeline.

## Search

- directory filters: small client-side dataset and instant filtering
- full text: Pagefind built from final static HTML
- later: optional numeric filters generated from normalized metrics

## Charts

Charts are generated by Atlas from verified structured data. Third-party chart screenshots are not a normal ingestion asset. Time-series charting remains deferred until verified financial/KPI data is added.

## Market data

No real-time stock-price distribution is part of the architecture. Any later market-data feature must be snapshot/as-of based and pass the Source Policy / licensing review before implementation.

## Secrets

- `.env`, key files, and `secrets/` are Git-ignored.
- API credentials must be injected through environment variables / GitHub Actions Secrets when needed.
- `scripts/check-secrets.py` is a heuristic CI tripwire, not a complete substitute for provider-side key restrictions, GitHub secret scanning, or git-history review.
- Public browser JavaScript must never receive a server-side secret merely to call a protected API.

## Deployment workflow

```text
checkout
  ↓
setup-node 22.12.0
  ↓
npm install
  ↓
npm run validate
  ├─ data/constitution invariants
  └─ secret-pattern tripwire
  ↓
npm run build
  ├─ Astro → dist/
  └─ Pagefind → dist/pagefind/
  ↓
upload-pages-artifact
  ↓
deploy-pages
```

The repository does not currently contain a generated npm lockfile because the authoring sandbox could not reach the npm registry reliably. After the first normal dependency install, commit `package-lock.json` and change CI installation to `npm ci` for reproducible installs.


## Delivery architecture

The production path is:

`GitHub repository -> GitHub Actions validation/build -> GitHub Pages deployment -> browser-accessible HTTPS URL`

The repository and build artifacts are implementation infrastructure. The browser URL is the product surface. v0.1 is not considered complete while this chain stops before deployment.

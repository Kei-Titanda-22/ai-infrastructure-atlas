# v0.4 Scope — 決算データ

Status: **In progress**

v0.4は、単一時点の財務指標から、一次資料へ追跡可能な四半期・通期の決算履歴へ移行するフェーズである。

## データ契約

各決算期間は `src/data/financial-history.json` の独立レコードとして保持する。

必須属性:

- companyId
- quarterly / annual
- periodLabel
- endDate
- currency / unit
- accountingBasis
- sourceId
- verifiedAt
- revenue
- operatingProfit
- operatingMargin
- freeCashFlow
- capex

各指標は `value / status / basis` を持つ。値がない場合も null だけで済ませず、`not-collected / primary-source-unchecked / not-calculable / not-disclosed / not-applicable` の理由を保持する。

## 初期移行

- 既存の共通財務監査済み7社を時系列DBへ移植
- NVIDIAはFY2024〜FY2026の通期比較とQ2 FY2026〜Q2 FY2027の四半期比較を収録
- TSMCはQ2 2025 / Q1 2026 / Q2 2026の四半期比較を収録
- キオクシア、SK hynix、Micron、ASML、東京エレクトロンは既存監査済み期間を収録
- FCF / Capexは定義確認が未完了の期間を `not-collected` とし、推定値を入れない

## UI

`/financials/` を決算履歴の正規ページとする。

- 企業切替
- 四半期 / 通期を分離
- 売上高と営業利益率の自前SVG推移図
- 売上高 / 営業利益 / 営業利益率 / FCF / 設備投資の表
- 会計基準・報告単位・一次資料・検証日を同じ画面で表示
- 通貨換算を行わず、企業内の時系列比較を基本とする

## 検証

`scripts/validate-v04.py` で以下をCI検査する。

- companyId / sourceIdの存在と対応企業
- record ID重複
- quarterly / annualの種別
- 5指標のスキーマ
- populated / missing statusの整合性
- 営業利益率の再計算差異
- verifiedAtの存在
- 既存の営業利益率監査済み企業が時系列DBから欠落していないこと

## v0.4完了条件

初期移行だけではv0.4 Completeにしない。以下を満たして完了とする。

- 主要収録企業について複数期間の四半期・通期履歴を拡充

- 個社ページの財務セクションから時系列履歴へ接続

- 決算更新履歴を体系化
- build / Pagefind / v0.1〜v0.4 validators / GitHub Pages deployが成功
